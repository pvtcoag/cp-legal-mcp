Overview

What It Is

CP Legal MCP is a production remote Model Context Protocol server built for Australian legal research. It gives Claude (and other MCP clients) access to 21 specialised legal research tools covering case law, legislation, entity intelligence, regulatory decisions, ASX data, and matter management.

⚖️
Legal Research
Search, retrieve and analyse Australian case law and legislation via AustLII. Powered by Isaacus Kanon AI for semantic reranking, extractive QA, enrichment, and summarisation.
🏢
Entity Intelligence
Look up companies and persons by ABN, ACN, or name using ASIC Connect and the Australian Business Register (ABR). Returns registration status, type, directors/officers, and GST info.
📋
Matter Tracking
Every tool call is tagged to a matter reference and stored in PostgreSQL. Full audit trail, per-matter billing, and a web UI at /auslaw/matters for researchers and admins.
📡
Regulatory & Market Data
Search ASIC and ACCC regulatory decisions, and ASX market announcements. All via public data sources with retry logic and rate limiting.
🔐
OAuth 2.0 + PKCE
Full OAuth 2.0 Authorization Code + PKCE flow. Supports Claude Web, ChatGPT, Cursor, mcp-remote, and any RFC 7591 dynamic registration client.
👤
Admin Portal
Web-based admin panel at /auslaw/admin for user management, spend cap configuration, precedent watchlist, billing export, and system health.
Primary Use Case
Practitioners use Claude with this MCP server for NSW/QLD/Federal legal research — drafting research memos, checking limitation periods and filing deadlines, monitoring precedents, and looking up entities for advisory matters.

Request lifecycle

Per MCP POST /auslaw
1. Cloudflare CDN → Railway TLS termination
2. Express rate limiter (60 req/min per IP pre-auth)
3. authMiddleware — verifies Bearer token (DB hash lookup, then env fallback)
4. Per-user rate limiter (60 req/min post-auth)
5. spendCapMiddleware — checks monthly spend vs per-user / global cap (DB)
6. requestContext.run({ user }) — async context propagation
7. createMcpHandler() — fresh McpServer + StreamableHTTPServerTransport per request
8. Tool handler executes → may call auslaw-mcp, Isaacus, ASIC/ABR, ASX
9. recordMatterQuery() — fire-and-forget insert into matter_queries
10. res.on('close') → transport.close() + server.close()

Stateless by design

Each MCP request creates a fresh McpServer + StreamableHTTPServerTransport with sessionIdGenerator: undefined. No session state, no shared mutable objects. Safe for concurrent users and horizontal scaling. The auslaw-mcp client is also fresh per tool call.

Authentication & Access Control

🔑
Bearer Token (MCP)
All /mcp requests require Authorization: Bearer <token>. Verified against hashed value in PostgreSQL, then falls back to MCP_AUTH_TOKENS env var.
🔐
OAuth 2.0 + PKCE
Claude Web and ChatGPT use OAuth Authorization Code + PKCE (S256). Static client pre-registered via OAUTH_CLIENT_ID. Dynamic registration via /auslaw/oauth/register for mcp-remote/Cursor.
🍪
Session Cookie (Web UI)
HMAC-SHA256 signed cookie cvn_matters. 8-hour TTL. Contains username, admin flag, session version, expiry, and signature. HttpOnly, Secure, SameSite=Strict.

In-memory & DB caching
Several layers of caching minimise both cost and latency: Rerank cache (5 min, 100 entries) deduplicates identical Isaacus rerank calls. QA cache (200 entries, permanent) deduplicates extractAnswer calls by (document, question) pair. Enrichment cache (DB, permanent) eliminates repeat Kanon 2 Enricher charges. Search cache (5 min, 200 entries) deduplicates auslaw-mcp search calls. Spend cap cache (5 min per user) avoids a DB aggregate on every MCP request.

SOPs & Runbooks

SOP 1 — Add a new user

1. Navigate to /auslaw/admin/users/new
2. Enter username (lowercase, alphanumeric + hyphens)
3. Click "Create user"
4. Copy the token shown — displayed ONCE and cannot be recovered
5. Send via secure channel (not email)
6. User connects MCP client:
   Claude Web: Add as remote MCP server → OAuth flow handles auth
   Direct:     Authorization: Bearer <token> on POST /auslaw

SOP 2 — Rotate a compromised token

1. Navigate to /auslaw/admin/users/:username
2. Click "Rotate token"
3. New token displayed once — save immediately
4. Send new token to user via secure channel
5. Old token immediately invalid — all existing MCP sessions rejected
6. User must re-authenticate all clients with new token

SOP 3 — Force-log a user out of the web UI

1. Navigate to /auslaw/admin/users/:username
2. Click "Force logout all sessions"
3. Increments session_version in DB
4. All cvn_matters cookies for that user immediately invalid
5. User redirected to /auslaw/matters/login on next page load
6. Logged as event_type = 'force_logout'

SOP 4 — Set per-user spend cap

1. Navigate to /auslaw/admin/users/:username
2. Find the "Spend Cap" section
3. Enter USD amount (e.g. 50 = $50/month) — leave blank for global default
4. Click "Set cap"
5. When cap reached: tool calls return HTTP 429, error: spend_cap_exceeded
6. To remove: clear field and save → falls back to global default

SOP 5 — Set global spend cap

1. Navigate to /auslaw/admin/config
2. spend_cap_monthly_per_user_usd → global default per user (USD)
3. spend_cap_alert_threshold_pct  → alert threshold (default 80%)
4. spend_cap_monthly_global_usd   → optional hard cap across ALL users
5. Changes apply immediately — no restart required

SOP 6 — Recover admin access (locked out)

1. Railway → cp-legal-mcp service → Variables
2. Add: RECOVERY_TOKEN = [40+ char random string]
          e.g. openssl rand -base64 32
3. Save → redeploy
4. Go to https://mcp.example.com/auslaw/matters/login
5. Username: recovery    Password: [the RECOVERY_TOKEN value]
6. Fix real admin account from /auslaw/admin/users
7. IMPORTANT: Remove RECOVERY_TOKEN from Railway immediately
8. Save → redeploy to clear recovery access

SOP 7 — auslaw-mcp is unreachable

Diagnosis:
  curl https://mcp.example.com/auslaw/health/upstream

Common causes:
  A) auslaw-mcp crashed → restart from Railway dashboard
  B) AUSLAW_BASE_URL wrong → must use Railway private domain:
     http://[service].railway.internal:3000
  C) Not co-located in same Railway project → private networking requires same project
